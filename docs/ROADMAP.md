Текущая версия — 1.1.0 (см. [CHANGELOG.md](CHANGELOG.md)).
Статусы: ✅ сделано · 🔜 запланировано · 💤 кандидат (не обещано).

## Ближайшие кандидаты

- 🔜 **Ф2: красно-зелёное сравнение замены в редакторе** (Zed-стиль):
  удалённый текст — красным фоном, вставленный — зелёным, поверх — клавиши
  keep/reject. Потребуется собственный `IAnnotationModel` + painter и работа
  с позициями при потоковой генерации. Основа уже есть: command/handler,
  карточка, клиент движка, потоковый «призрачный» предпросмотр (Ф1, ADR-11).
- 💤 **Аудит `db_help` и `db_listMacros`**: [SECURITY.md](SECURITY.md) обещает
  журналирование всех функций, но эти две (read-only справки) сейчас событий
  не пишут. Привести в соответствие: либо писать события, либо уточнить
  формулировку в доках.
- 💤 **Подсказка при ошибке `25P02`** («current transaction is aborted…»):
  распознавать и дописывать понятное «нужен Rollback» к тексту ошибки.
- 💤 **Состояние автокоммита в отчёте `db_getContext`**: явно показывать
  `autocommit on/off` и подсказку про Commit/Rollback.
- 💤 **Свой OpenAI-совместимый клиент** для правки выделения — как fallback,
  когда штатный профиль ИИ DBeaver недоступен (не настроен/сломан).
- 💤 **Выбор профиля ИИ для правки**: сейчас всегда используется профиль
  по умолчанию DBeaver; отдельная настройка (`edit.profile`?) — если появится
  потребность.

## Порядок работ

1. Аудит `db_help` / `db_listMacros` — мелкое, закрывает расхождение в доках;
2. `db_getContext` — автокоммит (мелкое, полезное в ежедневной работе);
3. Ф2 — диф в редакторе (крупное; делать после обкатки Ф1 на рабочих местах);
4. остальное — по потребности.

## Принципы

- никаких патчей DBeaver — только публичные API и штатные расширения;
- изменяющие операции — с подтверждением, лимитами и журналом аудита;
- документация (`docs/`) обновляется вместе с кодом;
- новые настройки — с безопасными значениями по умолчанию.

# План развития AI SQL for DBeaver

Текущая версия — 1.5.0 (см. [CHANGELOG.md](CHANGELOG.md)).
Статусы: ✅ сделано · 🔜 запланировано · 💤 кандидат (не обещано).

## Сделано в 1.5.0 (enterprise-уровень)

- ✅ **Корпоративная политика** (`ai-sql-enterprise.properties` /
  `-Daisql.enterprise.policy`): lock-down настроек ИБ, `tools.disabled`,
  fail-closed (ADR-13).
- ✅ **Промпт-инъекции**: режимы `injection.mode=off|flag|strict`
  (блокировка угона модели в strict) + fence «данные, не инструкции»
  для DDL и образцов строк (ADR-14).
- ✅ **Детекция ПДн по значению**: email/телефон/карта (Лун)/ИНН/СНИЛС —
  защита `SELECT *` и вычислимых колонок (ADR-15).
- ✅ **Экспорт аудита в SIEM** (UDP syslog, RFC 5424-подобный формат),
  поля `host`/`session`/`seq`, права 0600 (ADR-16).
- ✅ **`db_getTableSample`** (образцы строк, паритет с DBeaver PRO)
  и **`db_searchObjects`** (schema linking для больших схем) (ADR-17).
- ✅ **SqlErrorHints** — корректирующий цикл: типовые ошибки сопровождаются
  подсказкой «что делать» для модели.
- ✅ Аудит `db_help`/`db_listMacros` (было расхождение с SECURITY.md).
- ✅ CI (GitHub Actions): матрица DBeaver CE 26.1.5/26.2.2, автозагрузка,
  кэш, все 442 офлайн-проверки.
- ✅ Страница настроек: «Статус защиты», поля новых настроек, проверка
  целостности журнала, тест syslog, блокировка полей политикой.

## Ближайшие кандидаты

- 💤 **MCP-сервер**: экспонировать тулбокс `db_*` как MCP-сервер для
  внешних агентов (DataGrip 2025.2 и DBeaver PRO уже так делают) —
  потребуется отдельный транспорт и аутентификация.
- 💤 **Библиотека проверенных запросов**: авто-предложения пар
  «вопрос → SQL» из успешных выполнений (аналог Tool Memory у Vanna.ai)
  с ручным подтверждением пользователя.
- 💤 **Токен-метрика**: учёт потребления модели (AIUsage) в аудите
  и на странице настроек.
- 💤 **Свой OpenAI-совместимый клиент** для правки выделения — как fallback,
  когда штатный профиль ИИ DBeaver недоступен.
- 💤 **Windows/macOS**: install.ps1/install.command — сборка платформонезависима,
  нужна упаковка установки и проверка отрисовки диффа.

## Порядок работ

1. MCP-сервер — спроектировать транспорт (stdio/http) и модель
   подтверждений для внешних клиентов;
2. библиотека проверенных запросов — поверх журнала аудита;
3. остальное — по потребности.

## Принципы

- никаких патчей DBeaver — только публичные API и штатные расширения;
- изменяющие операции — с подтверждением, лимитами и журналом аудита;
- новые настройки — с безопасными значениями по умолчанию;
- документация (`docs/`) обновляется вместе с кодом;
- каждое изменение безопасности — офлайн-тестами в `tests/src`.

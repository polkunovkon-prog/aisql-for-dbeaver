# Журнал архитектурных решений (ADR)

Решения приняты в ходе проектирования версии 1.0.0 и фиксируют ответы
на вопросы «почему так, а не иначе».

---

## ADR-1. Два отдельных OSGi-бандла вместо патча jar-ов DBeaver

**Контекст.** Пилотный плагин поставлялся патчеными jar-ами DBeaver
(`*.jar.dbeaver-orig` — побочный след). Патчи ломаются при каждом обновлении
DBeaver и смешивают наш код с вендорным.

**Решение.** Два бандла: `com.pka.dbeaver.aisql.core` (классификация, политики,
аудит, AI-функции) и `com.pka.dbeaver.aisql.ui` (команды, настройки, промпты,
иконки). Регистрация — только штатные точки расширения
(`com.dbeaver.ai.function`, `org.eclipse.ui.*`), вендорные jar-ы не изменяются.

**Следствия.** Установка/удаление — копирование файлов; UI можно обновлять
независимо; ядро тестируется без SWT/UI.

## ADR-2. Классификация SQL — парсером DBeaver, а не токенными эвристиками

**Контекст.** Нужно надёжно отличать read-only запросы от изменяющих, включая
скрипты, `$$`-блоки, комментарии, строки с `;`.

**Решение.** `SQLClassifier` использует `SQLScriptParser` + `SQLQuery.getType()`
(категории SQL/DML/DDL/TCL/…); для «UNKNOWN» (SHOW, DESCRIBE, EXPLAIN, VALUES,
TABLE, PRAGMA) решение принимается по первому ключевому слову; `SELECT/WITH …
INTO` считается записью. Тип оператора (QUERY vs SCRIPT) выбирает тот же
классификатор.

**Следствия.** Поведение совпадает со штатным выполнением DBeaver на этой же
СУБД. Для тестов добавлена шов-точка `SqlClassifier.classify(text, category)` —
категория подставляется напрямую, без запуска платформы.

## ADR-3. Профили безопасности подключений

**Контекст.** Разным подключениям нужен разный уровень доверия: прод —
только чтение, dev — свободнее.

**Решение.** Профили `READ_ONLY` / `STANDARD` (по умолчанию) / `FULL`.
Правило ищется по имени подключения: точное совпадение ключа
`policy.profile.<имя>`, затем glob-маски (`*`, `?`) в алфавитном порядке;
иначе — `policy.defaultProfile`. В READ_ONLY запрещены изменяющие операторы
и `EXPLAIN ANALYZE` (он выполняет запрос). В FULL отключаются
`policy.forbidden` и маскирование.

**Отклонено.** Привязка профиля к драйверу/URL — имя подключения удобнее
для пользователя и стабильнее между средами.

## ADR-4. Маскирование — на выходе функции, до отправки в модель

**Контекст.** Значения секретных колонок не должны попадать в языковую модель.

**Решение.** Правила `таблица.колонка=замена` (Globs, `*` = всё, замена по
умолчанию `***`). Замена подставляется при формировании текстового ответа
AI-функции — реальные значения остаются локально в DBeaver и в модель
не отправляются. Работает в профилях != FULL.

**Отклонено.** Маскирование на уровне SQL (переписывание запроса) — хрупко
и заметно искажает выполняемый SQL; скрытие целиком колонок без настройки —
слишком грубо.

## ADR-5. Аудит v2: JSONL + цепочка SHA-256

**Контекст.** Нужен след «что и когда выполнялось», пригодный для проверки
на подделку, без внешних зависимостей.

**Решение.** `ai-sql-audit.jsonl`, каждая строка —
`hash = SHA256(prev + "\n" + строка без hash)`, первая ссылается на `genesis`.
Ротация по `audit.maxBytes`/`maxFiles`, цепочка продолжается после ротации.
Опционально `audit.redactLiterals` (замена строковых литералов на `'?'`).
Программная проверка: `AisqlAudit.verify(Path)` + `releng/verify-audit.py`.
Старый лог `ai-sql-audit.log` не трогается.

**Ограничения (приняты сознательно).** Журнал — файл, его можно удалить;
это память о событиях, а не защита от уничтожения (нужен внешний сбор логов).

## ADR-6. Команды «выделил → спросил» без автоотправки

**Контекст.** Идея фичи: выделил текст → спросил ИИ. Но отправка вопроса
от имени пользователя без его контроля недопустима (модель могла бы получать
данные без явного действия).

**Решение.** Команда формирует промпт (цитата с `>`, контекст подключения,
«Вопрос: ») и **вставляет его в поле ввода ИИ-чата**, ставит фокус. Отправку
выполняет пользователь. Реализация — рекурсивный поиск `PromptComposite`
в `AIChatControl` (без рантайм-зависимостей от внутренних классов чужого
бандла); при неудаче — буфер обмена + диалог.

**Следствия.** Работает стабильно между версиями DBeaver UI; при «переезде»
вендорного UI команда деградирует до буфера обмена, а не падает.

## ADR-7. Сборка и установка без p2/Maven

**Контекст.** Robot-сборка Tycho/Maven на целевой машине избыточна:
версия DBeaver везде одна, зависимостей вне самого DBeaver нет.

**Решение.** `releng/build.sh`: `javac --release 21` против всех jar-ов
установленного DBeaver → jar-ы → `dist/`. Установка: dropins
(`/usr/share/dbeaver-ce/dropins/plugins`) + регистрация бандлов — прямой,
идемпотентный append записей в `bundles.info` с резервной копией (p2-реконцилер
на целевом DBeaver CE каталог `dropins` не обрабатывает — проверено на месте).
Контрольный запуск в install.sh: сначала headless-запуск (`xvfb-run`) от имени
рабочего пользователя (как в реальности), затем — при необходимости — от root;
результат проверки не отменяет установку, а лишь подтверждает её.

**Отклонено.** Полноценный p2-сайт с директором — заметно сложнее в поддержке
без выигрыша при единой версии DBeaver.

## ADR-8. Настройки — properties-файл рядом с ai-tools.json

**Контекст.** Настройки должны переживать переустановку плагина, легко
копироваться между рабочими местами и быть доступными из runtime-кода
в момент вызова функций.

**Решение.** `ai-sql-plugin.properties` в `<workspace>/.metadata/.config/`
(рядом с `ai-tools.json` DBeaver). Страница Preferences — удобный редактор
этого файла; параметры читаются с кэшем по mtime+size и применяются «на лету».
Запись атомарная (tmp + ATOMIC_MOVE). Тестовый хук `-Daisql.config.dir`
подменяет каталог.

**Отклонено.** `preferences.ini`/`InstanceScope` — неудобно переносить между
машинами и проверять инструментами.

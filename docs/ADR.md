# Журнал архитектурных решений (ADR)

Решения приняты в ходе проектирования версии 1.0.0 и фиксируют ответы
на вопросы «почему так, а не иначе».

---

## ADR-1. Два отдельных OSGi-бандла вместо патча jar-ов DBeaver

**Контекст.** Пилотный плагин поставлялся патчеными jar-ами DBeaver
(`*.jar.dbeaver-orig` — побочный след). Патчи ломаются при каждом обновлении
DBeaver и смешивают наш код с вендорным.

**Решение.** Два бандла: `com.aisql.dbeaver.core` (классификация, политики,
аудит, AI-функции) и `com.aisql.dbeaver.ui` (команды, настройки, промпты,
иконки). Регистрация — только штатные точки расширения
(`com.dbeaver.ai.function`, `org.eclipse.ui.*`), вендорные jar-ы не изменяются.

**Следствия.** Установка/удаление — копирование файлов; UI можно обновлять
независимо; ядро тестируется без SWT/UI.

---

## ADR-2. Классификация SQL — парсером DBeaver, а не токенными эвристиками

**Контекст.** Нужно надёжно отличать read-only запросы от изменяющих, включая
скрипты, `$$`-блоки, комментарии, строки с `;`.

**Решение.** `SQLClassifier` использует `SQLScriptParser` + `SQLQuery.getType()`
(категории SQL/DML/DDL/TCL/…); для «UNKNOWN» (SHOW, DESCRIBE, EXPLAIN, VALUES,
TABLE, PRAGMA) решение принимается по первому ключевому слову; `SELECT/WITH …
INTO` считается записью. Тип оператора (QUERY vs SCRIPT) выбирает тот же
классификатор.

**Следствия.** Поведение совпадает со штатным выполнением DBeaver на этой же
СУБД. Для тестов добавлена шов-точка `SqlClassifier.classify(text, category)` —
категория подставляется напрямую, без запуска платформы.

## ADR-3. Профили безопасности подключений

**Контекст.** Разным подключениям нужен разный уровень доверия: прод —
только чтение, dev — свободнее.

**Решение.** Профили `READ_ONLY` / `STANDARD` (по умолчанию) / `FULL`.
Правило ищется по имени подключения: точное совпадение ключа
`policy.profile.<имя>`, затем glob-маски (`*`, `?`) в алфавитном порядке;
иначе — `policy.defaultProfile`. В READ_ONLY запрещены изменяющие операторы
и `EXPLAIN ANALYZE` (он выполняет запрос). В FULL отключаются
`policy.forbidden` и маскирование.

**Отклонено.** Привязка профиля к драйверу/URL — имя подключения удобнее
для пользователя и стабильнее между средами.

---

## ADR-4. Маскирование — на выходе функции, до отправки в модель

**Контекст.** Значения секретных колонок не должны попадать в языковую модель.

**Решение.** Правила `таблица.колонка=замена` (Globs, `*` = всё, замена по
умолчанию `***`). Замена подставляется при формировании текстового ответа
AI-функции — реальные значения остаются локально в DBeaver и в модель
не отправляются. Работает в профилях != FULL.

**Отклонено.** Маскирование на уровне SQL (переписывание запроса) — хрупко
и заметно искажает выполняемый SQL; скрытие целиком колонок без настройки —
слишком грубо.

## ADR-5. Аудит v2: JSONL + цепочка SHA-256

**Контекст.** Нужен след «что и когда выполнялось», пригодный для проверки
на подделку, без внешних зависимостей.

**Решение.** `ai-sql-audit.jsonl`, каждая строка —
`hash = SHA256(prev + "\n" + строка без hash)`, первая ссылается на `genesis`.
Ротация по `audit.maxBytes`/`maxFiles`, цепочка продолжается после ротации.
Опционально `audit.redactLiterals` (замена строковых литералов на `'?'`).
Программная проверка: `AisqlAudit.verify(Path)` + `releng/verify-audit.py`.
Старый лог `ai-sql-audit.log` не трогается.

**Ограничения (приняты сознательно).** Журнал — файл, его можно удалить;
это память о событиях, а не защита от уничтожения (нужен внешний сбор логов).

## ADR-6. Команды «выделил → спросил» без автоотправки

**Контекст.** Идея фичи: выделил текст → спросил ИИ. Но отправка вопроса
от имени пользователя без его контроля недопустима (модель могла бы получать
данные без явного действия).

**Решение.** Команда формирует промпт (цитата с `>`, контекст подключения,
«Вопрос: ») и **вставляет его в поле ввода ИИ-чата**, ставит фокус. Отправку
выполняет пользователь. Реализация — рекурсивный поиск `PromptComposite`
в `AIChatControl` (без рантайм-зависимостей от внутренних классов чужого
бандла); при неудаче — буфер обмена + диалог.

**Следствия.** Работает стабильно между версиями DBeaver UI; при «переезде»
вендорного UI команда деградирует до буфера обмена, а не падает.

## ADR-7. Сборка и установка без p2/Maven

**Контекст.** Robot-сборка Tycho/Maven на целевой машине избыточна:
версия DBeaver везде одна, зависимостей вне самого DBeaver нет.

**Решение.** `releng/build.sh`: `javac --release 21` против всех jar-ов
установленного DBeaver → jar-ы → `dist/`. Установка: dropins
(`/usr/share/dbeaver-ce/dropins/plugins`) + регистрация бандлов — прямой,
идемпотентный append записей в `bundles.info` с резервной копией (p2-реконцилер
на целевом DBeaver CE каталог `dropins` не обрабатывает — проверено на месте).
Контрольный запуск в install.sh: сначала headless-запуск (`xvfb-run`) от имени
рабочего пользователя (как в реальности), затем — при необходимости — от root;
результат проверки не отменяет установку, а лишь подтверждает её.

**Отклонено.** Полноценный p2-сайт с директором — заметно сложнее в поддержке
без выигрыша при единой версии DBeaver.

## ADR-8. Настройки — properties-файл рядом с ai-tools.json

**Контекст.** Настройки должны переживать переустановку плагина, легко
копироваться между рабочими местами и быть доступными из runtime-кода
в момент вызова функций.

**Решение.** `ai-sql-plugin.properties` в `<workspace>/.metadata/.config/`
(рядом с `ai-tools.json` DBeaver). Страница Preferences — удобный редактор
этого файла; параметры читаются с кэшем по mtime+size и применяются «на лету».
Запись атомарная (tmp + ATOMIC_MOVE). Тестовый хук `-Daisql.config.dir`
подменяет каталог.

**Отклонено.** `preferences.ini`/`InstanceScope` — неудобно переносить между
машинами и проверять инструментами.

## ADR-9. Singleton и статическая страница настроек (итоги приёмочного теста)

**Контекст.** При первом интерфейсном тесте ИИ-чат сообщил об отсутствии
инструментов выполнения SQL, хотя бандлы грузились. Диагностика по `.log`:
Equinox игнорировал расширения ядра без `singleton:=true` («The extensions
and extension-points from the bundle "com.aisql.dbeaver.core" are
ignored. The bundle is not marked as singleton»), а динамическая
регистрация alias-страницы падала («Unauthorized access to the
ExtensionRegistry.addContribution() method» — Equinox требует служебный
токен доступа, недоступный сторонним бандлам).

**Решение.**

- `Bundle-SymbolicName: com.aisql.dbeaver.core;singleton:=true` —
  штатное требование Eclipse к бандлам, дающим точки расширения;
- страница настроек регистрируется **статически** под id
  `com.dbeaver.preferences.ai.tools` — именно его открывает пункт
  «Configure AI Tools…» карточек ИИ
  (`org.jkiss.dbeaver.ui.ai.chat.controls.AIFunctionAllowMenu`);
  динамический регистратор `PreferenceAliasRegistrar` удалён.

**Отклонено.** Динамическая регистрация alias через `IExtensionRegistry.
addContribution` — не работает без вендорского токена; второй экземпляр
страницы под собственным id — дублирование пункта в дереве настроек.

**Риск.** Если вендор в будущей версии зарегистрирует этот же id — возможен
конфликт страниц; целевая версия DBeaver зафиксирована (26.2.2), риск принят.

**Побочная находка.** P2-реконцилер dropins всё же подхватывает jar-ы из
каталога установки `/usr/share/dbeaver-ce/dropins` — но только когда его
область данных (`p2/`) доступна на запись; в системной установке она
root-овая, поэтому штатная регистрация бандлов через `bundles.info`
(см. ADR-7) остаётся основным механизмом.

## ADR-10. Сброс кэша OSGi при переустановке (итоги второго прогона)

**Контекст.** После исправлений по ADR-9 переустановка в системный DBeaver
не дала эффекта: контрольный запуск снова сообщил «…are ignored. The bundle
is not marked as singleton», хотя в установленном jar-е манифест уже был
исправлен (проверено побайтовым сравнением со сборкой). Причина — кэш
Equinox в `configuration/org.eclipse.osgi`: при совпадении **пути и версии**
бандла фреймворк переиспользует ранее закешированные данные (включая
манифест) и не перечитывает заменённый jar. Обновления p2 по этой причине
всегда меняют версии бандлов, а ручная замена файла под той же версией
(`1.0.0`) кэш не инвалидирует.

**Решение.** `install.sh` (шаг 2) и `uninstall.sh` безусловно удаляют
`<DBeaver>/configuration/org.eclipse.osgi` — каталог чисто служебный и
пересоздаётся при запуске. Контрольная проверка `install.sh` при неудаче
дополнительно ищет в журнале строку «…are ignored…» и печатает диагноз
про кэш.

**Отклонено.** Менять версию бандла при каждой пересборке — усложняет
сопровождение ради обхода кэша; советовать пользователю `-clean` вручную —
недетерминированно и легко забывается.

**Дополнение (вторая приёмка, тот же день).** Пользовательские запуски
DBeaver используют отдельный каталог конфигурации: системная configuration
недоступна им на запись, и продукт уводит её в персональный install-data
(`~/.local/share/DBeaverData/install-data/<product>/<version>/` — на этой
машине это и есть рабочий случай пользователя). Оба кэша Equinox лежат там:
данные бандлов (`org.eclipse.osgi`, включая `framework.info.*`) и **модель
реестра расширений** (`org.eclipse.core.runtime`, файлы `.mainData.*`,
`.contributions.*` и т.п.). Список бандлов при этом берётся из системного
`bundles.info`, а из install-data читаются кэши. Без сброса этих кэшей после
обновления jar-ов сессия пользователя поднимала модель старой сборки: ранний
старт пытался загрузить удалённый класс `PreferenceAliasRegistrar`
(ClassNotFoundException из `EarlyStartupRunnable`; строка класса найдена
grep-ом прямо в `.mainData.2`), расширения не регистрировались, и ИИ-чат
снова оставался без инструментов; исправная пересборка при этом
подтверждалась только в песочнице (у неё своя configuration). Поэтому
`install.sh`/`uninstall.sh` сбрасывают обе пары каталогов во всех известных
областях конфигурации: системной, персональной install-data и следах старых
Eclipse в домашнем каталоге (`~/eclipse/configuration`,
`~/.eclipse/*/configuration` — дополнительные, не основные). Если DBeaver
пользователя запущен, установка предупреждает, что сброс не сработает —
процесс восстановит кэш при выходе.

## ADR-11. Правка выделения ИИ прямо в SQL-редакторе (Ctrl+Alt+E)

**Контекст.** Команды «выделил → спросил» (`Ctrl+Alt+A`) только вставляют
промпт в чат: результат правки нужно вручную переносить обратно в редактор.
Запрошен сценарий «как в Zed»: выделил фрагмент → горячая клавиша →
инструкция → замена видна прямо в редакторе → применяется одним действием.
Требования: работает в текущей версии DBeaver CE (26.2.2) **без патчей**
вендорных jar-ов, использует уже настроенную модель DBeaver, ничего
не выполняет в базе данных.

**Решение.**

- Стратегия — «в редакторе» (inline); отдельное окно не понадобилось:
  проверка публичных API показала, что всё реализуемо без патчей.
- Команда `com.aisql.dbeaver.commands.editSelection` (`Ctrl+Alt+E`
  в контексте SQL-редактора, пункт контекстного меню) + карточка (`Dialog`):
  поле инструкции (`Enter` — сгенерировать, `Esc` — отмена), кнопки
  «Сгенерировать» / «Применить» / «В чат» / «Отмена». Окно немодальное
  и не закрывается при клике в редактор — предпросмотр можно изучить.
- Модель — штатный профиль ИИ DBeaver (`AISettingsManager` → профиль по
  умолчанию → `AIEngineDescriptor.createEngineInstance` → `AIEngine`) —
  тот же движок, что у чата; отдельные URL/ключ не нужны. Ответ запрашивается
  потоком (`requestCompletionStream`, дельты дописываются к накопленному
  тексту), для движков без стрима есть резервный обычный запрос. Весь доступ
  к внутренним API `model.ai` изолирован в классе `AiEditClient`.
- Предпросмотр — «призрачный» текст: собственная копия штатного, но нигде
  не задействованного `SQLSuggestionTextPainter` (пакет
  `org.jkiss.dbeaver.ui.editors.sql.suggestion`), зелёный текст на светлом
  фоне, позиция — конец выделения
  (`ProjectionViewer.modelOffset2WidgetOffset`). Пока идёт генерация, текст
  дописывается с троттлингом 100 мс.
- Применение — замена выделения ответом модели. Перед заменой проверяется,
  что выделенный участок не изменился (иначе правка отклоняется «как
  устаревшая»); замена выполняется через `IRewriteTarget.
  beginCompoundChange()/endCompoundChange()`, поэтому **один `Ctrl+Z`
  отменяет всю правку**. В БД ничего не выполняется — меняется только текст
  редактора.
- Режимы: `edit.applyMode=preview` (по умолчанию — применение по кнопке)
  или `direct` (сразу после генерации). Прочие настройки: `edit.enabled`,
  `edit.maxSelectionChars` (4000 символов), `edit.audit`.
- Страховка «В чат»: если правку нужно обсудить — тот же запрос с цитатой
  фрагмента уходит в ИИ-чат без применения (поведение `Ctrl+Alt+A`).
- Аудит: события `ai_edit` (applied / canceled / chat / error) с режимом,
  размерами фрагмента и результата и инструкцией одной строкой. Текст
  фрагмента и ответ модели в журнал **не пишутся**.

**Отклонено.**

- Патч вендорных jar-ов (например, встраивание в существующий
  `AITranslateHandler` и штатную всплывашку) — нарушает ADR-1; проверено,
  что не требуется: `TextViewer.getRewriteTarget()`, `getViewer()` и painter
  подсказок доступны публично;
- отдельное окно правки (запасной вариант Ф0) — хуже по UX; остаётся
  будущим fallback-ом на случай изменения API;
- собственный OpenAI-совместимый клиент для правки — дублирует настройки
  модели/ключа, которые у пользователя уже сделаны в DBeaver;
- подмена содержимого штатного автодополнения (`showCompletion`) — публичного
  API для этого нет;
- красно-зелёное сравнение (диф) в первой версии — отложено в Ф2
  (см. [ROADMAP.md](ROADMAP.md)): требует собственного `IAnnotationModel`
  и заметно больше работы.

**Следствия.**

- Внутренние API DBeaver задействованы из изолированных классов
  (`AiEditClient`, `AiEditGhost`, `AiEditSession`); при обновлении DBeaver
  поломка локализуема, остальные функции плагина не затрагиваются.
- Выделенный фрагмент уходит в выбранную модель — как при ручной вставке
  в чат. Маскирование (`mask.*`) на правку не распространяется: это текст
  самого пользователя, а не результат запроса (зафиксировано в SECURITY.md).
- Пользователь всегда видит предпросмотр до применения (в режиме `preview`),
  решение остаётся за ним; «устаревшая» правка не применяется.

## ADR-12. Точечные замены в правке выделения: клиентский дифф и вертикальный отступ (Ф2)

**Контекст.** Ф1 (ADR-11) показывала ответ модели «призраком» целиком:
пользователь видел новую версию, но не «что именно изменилось», и не мог
принять изменения частично. Запрошен стиль Zed: замены на своих местах,
список замен, выборочное применение. Ограничения прежние: без патчей
DBeaver, только публичные API, модель — локальная и ненадёжная в форматах.

**Решение.**

- **Дифф считается на клиенте** (`AiEditDiff`, LCS по строкам): модель,
  как и раньше, возвращает полный текст, а список замен строит плагин.
  Логика — чистые функции, покрыта офлайн-тестами; инвариант «применение
  всех замен к исходнику даёт ровно ответ модели» проверяется тестами
  (включая CRLF и хвостовые переводы строк).
- **Единица диффа — строка вместе с переводом строки.** Замена описывает
  точный диапазон исходного текста (байт-в-байт), поэтому применима
  к документу как есть; применение — от последней замены к первой, чтобы
  не сдвигать смещения; всё — в одном compound change (один `Ctrl+Z`).
- **Подсветка «стало» — зарезервированное вертикальное место строки**
  (`StyledText.setLineVerticalIndent`, публичный API; тем же приёмом
  DBeaver рисует многострочные подсказки автодополнения). Под строкой
  резервируется место, в нём текст замены рисуют собственные `PaintListener`
  и `LineBackgroundListener`; документ не меняется, нумерация строк
  не сдвигается. «Было» — красный фон и зачёркивание диапазона.
- **Предпросмотр — надстройка, а не правка документа:** при любом изменении
  документа он снимается («устарело»), замены предлагается сгенерировать
  заново; применение заведомо устаревших замен невозможно.
- **Режимы:** `edit.previewMode=diff` (по умолчанию) — точечные замены;
  `full` — прежний «призрак» (страховка на случай проблем отрисовки
  на конкретной платформе/теме).

**Отклонено.**

- Просить у модели структурированный список правок (JSON/patch): локальная
  модель ошибается в форматах, и сбой формата ломал бы всю правку; полный
  текст — единственный формат, который она выдаёт надёжно;
- собственный `IAnnotationModel`: тяжелее и конфликтует с аннотациями
  DBeaver; painter + вертикальный отступ дают тот же визуальный результат;
- вставка строк «стало» в документ: сдвинула бы нумерацию строк и стек
  undo; эмуляция через отступ решает это без правки документа;
- отдельные undo-операции на каждую замену: ломает «один `Ctrl+Z`
  на всю правку».

**Следствия.**

- Верхняя граница диффа (`MAX_CELLS`, ~4 млн ячеек LCS): на очень больших
  фрагментах предпросмотр вырождается в одну замену «весь фрагмент»
  (поведение Ф1) — деградация плавная, без отказа;
- painter и слушатели всегда снимаются при закрытии карточки/применении;
  ошибки отрисовки не могут «сломать» редактор;
- режим `full` остаётся запасным и использует тот же конвейер
  генерации/применения.

# Использование AI SQL for DBeaver

## 1. Инструменты ИИ-чата (тулбокс `db`)

Плагин добавляет в ИИ-чат DBeaver 11 функций категории
**«Выполнение SQL через ИИ»**. Модель вызывает их сама, когда это уместно;
пользователь видит карточку подтверждения (Allow / Deny) для опасных вызовов.

| Функция | Что делает | Подтверждение по умолчанию |
|---|---|---|
| `db_runQuery` | Один read-only запрос (SELECT/WITH/SHOW/DESCRIBE/EXPLAIN/VALUES/TABLE), возвращает строки | ASK |
| `db_executeSql` | Любой SQL: DML, DDL, DCL, скрипты из нескольких операторов | ASK |
| `db_getContext` | Сведения о подключении: СУБД, версия, пользователь, схема, профиль | всегда разрешено |
| `db_listObjects` | Объекты БД: таблицы, представления, функции, процедуры… | всегда разрешено |
| `db_getObjectDdl` | DDL объекта: `CREATE TABLE/FUNCTION/...` | всегда разрешено |
| `db_explain` | План выполнения запроса | всегда разрешено |
| `db_help` | Справка по инструментам и ограничениям | всегда разрешено |
| `db_listMacros` | Список сохранённых макросов | всегда разрешено |
| `db_runMacro` | Выполнить макрос с подстановкой `${параметр}` | ASK |
| `db_defineMacro` | Создать/обновить макрос (история — 5 версий) | ASK |
| `db_deleteMacro` | Удалить макрос | ASK |

Режим подтверждения меняется штатным меню карточки: **▾ → Allow this tool
always / Ask every time / Deny**. Значения хранит DBeaver в `ai-tools.json`,
плагин их не дублирует. Просмотр — Preferences → AI → «Инструменты ИИ».

### Примеры фраз

- «Сколько строк в таблице `orders`?» → `db_runQuery`
- «Покажи первые 5 строк `customers`» → `db_runQuery`
- «Какие функции и процедуры есть в базе?» → `db_listObjects`
- «Покажи SQL-определение функции `calc_bonus`» → `db_getObjectDdl`
- «Создай таблицу `t_probe(id int, name varchar(50))`» → `db_executeSql` + карточка
- «Вставь в `t_probe` строку (1, 'тест')» → `db_executeSql` + карточка
- «Какая СУБД, версия и текущий пользователь?» → `db_getContext`
- «Оцени план выполнения: SELECT … » → `db_explain`
- «Запомни макрос `today`: SELECT CURRENT_DATE» → `db_defineMacro`
- «Выполни макрос `today`» → `db_runMacro`

Модель сама выбирает инструмент по описанию; можно указывать явно:
«используй `db_executeSql`».

## 2. Команды «выделил → спросил»

| Команда | Где | Горячая клавиша |
|---|---|---|
| Спросить ИИ о выделенном | SQL-редактор (есть выделение) — контекстное меню | `Ctrl+Alt+A` |
| Править выделенное ИИ | SQL-редактор (есть выделение) — контекстное меню | `Ctrl+Alt+E` |
| Спросить ИИ о выделенных строках/ячейках | таблица результатов — панель инструментов и `Ctrl+Alt+I` | `Ctrl+Alt+I` |
| Настройки плагина | панель ИИ-чата (кнопка с ползунками) | — |

Как это работает: плагин формирует короткий промпт с цитатой выделенного
(построчно, с `>`), именем подключения и завершением «Вопрос: » — и **вставляет
его в поле ввода уже открытого ИИ-чата**. Автоотправки нет: вопрос дописывает
пользователь. Если чат недоступен, промпт копируется в буфер обмена.

Ограничения цитаты: до 4000 символов выделения (строка — до 500), в таблице —
до 5 строк, ячейка — до 300 символов.

## 3. Правка выделения ИИ прямо в редакторе (`Ctrl+Alt+E`)

Сценарий «выделил → попросил → заменил», не покидая редактор (по мотивам
Zed): инструкция → генерация → **точечные замены с подсветкой прямо
в редакторе** → выборочное «Применить».

1. В SQL-редакторе выделите фрагмент (один запрос или несколько строк)
   и нажмите `Ctrl+Alt+E` (или контекстное меню → «Править выделенное ИИ»).
2. В карточке рядом с выделением введите инструкцию, например:
   - «сделай все имена в нижнем регистре»;
   - «добавь фильтр `WHERE dt >= CURRENT_DATE - 7`»;
   - «упрости: убери лишние обёртки, оставь нужные поля».

   `Enter` — сгенерировать, `Esc` — отмена.
3. По мере генерации в редакторе появляется предпросмотр замен: удаляемый
   текст подсвечен красным и зачёркнут, новый — зелёный, сразу после места
   замены. Это предпросмотр — **в базе данных ничего не выполняется**,
   документ не меняется (нумерация строк не сдвигается).
4. Проверьте замены:
   - список в карточке: «Замена N · стр. X–Y» и мера изменения «−2 +1»
     (удалено/добавлено строк), «перед стр. X» — для вставки;
   - `Alt+↓` / `Alt+↑` (в редакторе или в карточке) — переход между
     заменами; активная обведена рамкой;
   - галочки в списке — какие замены применять («Отметить все» / «Снять все»).
5. Нажмите **«Применить (N из M)»** (или «Применить все») — отмеченные
   замены вносятся **одной операцией**: один `Ctrl+Z` отменяет всю правку.
6. Либо **«В чат»** — тот же запрос с цитатой фрагмента уйдёт в ИИ-чат
   (без применения): удобно для длинных обсуждений; **«Отмена»** — закрыть
   карточку и ничего не менять.

Особенности:

- используется та же модель, что у ИИ-чата (профиль по умолчанию из
  `Preferences → AI`) — URL/ключ настраивать отдельно не нужно;
- если текст в редакторе изменился после генерации, предпросмотр снимается
  (статус «устарело»): замены не применяются, правку нужно запустить заново;
- режим `edit.applyMode=direct` применяет все найденные замены сразу после
  генерации (по умолчанию `preview` — применение по кнопке);
- режим `edit.previewMode=full` — прежний «призрачный» предпросмотр всего
  ответа целиком, без подсветки замен (запасной вариант);
- лимит выделения — `edit.maxSelectionChars` (4000 символов по умолчанию);
- применения, отмены и переходы «В чат» записываются в журнал аудита
  событиями `ai_edit` (текст фрагмента и ответ модели в журнал не пишутся);
  отключается настройкой `edit.audit`.

## 4. Страница настроек

`Window → Preferences → AI → «AI SQL: инструменты SQL»` (или кнопка с
ползунками в панели ИИ-чата). Все настройки хранятся в
`<workspace>/.metadata/.config/ai-sql-plugin.properties` рядом с `ai-tools.json`,
применяются **сразу после Apply**, перезапуск не нужен. Файл можно править
и вручную (изменения подхватываются при следующем обращении).

### 4.1. Профили безопасности подключений

Профиль определяется по имени подключения: сначала точное совпадение,
затем — glob-маски (`*`, `?`) в алфавитном порядке ключей.

| Профиль | Что разрешено |
|---|---|
| `READ_ONLY` | только чтение: SELECT/WITH/SHOW/DESCRIBE/EXPLAIN/VALUES/TABLE; EXPLAIN ANALYZE запрещён (может выполнять запрос) |
| `STANDARD` (по умолчанию) | плюс DML/DDL/DCL; действуют `policy.forbidden` и маскирование |
| `FULL` | всё; `policy.forbidden` и маскирование отключаются |

Ключи:

```properties
policy.defaultProfile=STANDARD
policy.profile.Sakila=READ_ONLY
policy.profile.prod-*=READ_ONLY
policy.profile.dev-*=FULL
```

### 4.2. Запрещённые конструкции (`policy.forbidden`)

Регулярные выражения (Java), по одному на строку (`;` и `\n` — разделители,
`#` — комментарий). Действуют во **всех профилях, кроме FULL**. Срабатывание
блокирует выполнение с сообщением о правиле.

```properties
policy.forbidden=DROP\s+TABLE;\nTRUNCATE\s+;\nALTER\s+SYSTEM
```

Это средство снижения рисков, а не защита от злоумышленника (см.
[SECURITY.md](SECURITY.md)).

### 4.3. Ограничения

| Ключ | По умолчанию | Смысл |
|---|---|---|
| `runQuery.strictReadOnly` | `true` | `db_runQuery` принимает только read-only операторы |
| `write.disableAutocommit` | `true` | перед изменяющими операторами автокоммит отключается (можно откатить) |
| `limit.maxRows` | `200` | максимум строк в ответе (жёсткий потолок 5000) |
| `limit.timeoutSec` | `60` | таймаут выполнения |
| `limit.maxPayloadChars` | `40000` | предел вывода для модели (потолок 200000, `0` — без ограничения) |
| `macros.maxBytes` | `65536` | максимальный размер макроса |

### 4.4. Маскирование данных (`mask.*`)

Правила вида `таблица.колонка=замена` (через `=`), по одному на строку;
`*` — любые символы; замену можно опустить — тогда `***`. Действует в профилях
`READ_ONLY`/`STANDARD` (в `FULL` отключается вместе с ограничениями).

```properties
mask.enabled=true
mask.rules=customers.email=***@***; *.password=***; sakila.*.phone=[скрыто]
```

Замена подставляется при формировании ответа для модели — реальные значения
остаются только локально в DBeaver и в модель не попадают. Маскирование видно
в `db_getContext` (число активных правил). Типовой набор для прода:
`*.password=***`, `*.token=***`, `customers.email=***` и т.п.

### 4.5. Журнал аудита

| Ключ | По умолчанию | Смысл |
|---|---|---|
| `audit.enabled` | `true` | вести журнал |
| `audit.redactLiterals` | `false` | заменять строковые литералы в SQL на `'?'` при записи |
| `audit.maxBytes` | 5242880 | размер до ротации (5 МБ) |
| `audit.maxFiles` | 5 | сколько файлов хранить (текущий + 4 повёрнутых) |

Файлы: `ai-sql-audit.jsonl`, `ai-sql-audit.jsonl.1` … `.N` — в каталоге
`.metadata/.config/`. Кнопки на странице настроек открывают журнал и каталог.
Формат и проверка целостности — в [SECURITY.md](SECURITY.md).

### 4.6. Правка выделения с ИИ (`edit.*`)

| Ключ | По умолчанию | Смысл |
|---|---|---|
| `edit.enabled` | `true` | включить правку выделения (`Ctrl+Alt+E`) |
| `edit.applyMode` | `preview` | `preview` — применять по кнопке; `direct` — сразу после генерации |
| `edit.previewMode` | `diff` | `diff` — предпросмотр точечных замен (подсветка «было/стало»); `full` — весь ответ целиком («призрак») |
| `edit.maxSelectionChars` | `4000` | максимум символов выделения (потолок 200000) |
| `edit.audit` | `true` | записывать применения/отмены правок в журнал аудита |

## 5. Макросы — «обучение» ИИ повторяемым операциям

Макрос — именованный SQL-скрипт с подстановками `${имя}` и `${1}`,`${2}`:

1. «Запомни макрос `daily_sales`: SELECT SUM(total) FROM orders WHERE dt = ${day}»;
2. `db_defineMacro` → карточка → файлы в `<workspace>/.metadata/.config/ai-macros/`:
   `daily_sales.sql` + `daily_sales.meta` (заголовок, описание, дата);
3. «Выполни макрос `daily_sales`, day=2026-10-16» → `db_runMacro`;
4. при перезаписи предыдущая версия сохраняется в `ai-macros/history/`
   (хранятся 5 последних версий).

Идентификатор макроса: латиница/цифры/`_ . -`, до 64 символов.

## 6. Горячие клавиши и файлы

| Что | Где |
|---|---|
| `Ctrl+Alt+A` | SQL-редактор: спросить ИИ о выделенном |
| `Ctrl+Alt+E` | SQL-редактор: править выделенное ИИ (замены + «Применить») |
| `Alt+↓` / `Alt+↑` | правка выделения: следующая/предыдущая замена (в редакторе и карточке) |
| `Ctrl+Alt+I` | таблица результатов: спросить ИИ о выделенных строках |
| Настройки | `<workspace>/.metadata/.config/ai-sql-plugin.properties` |
| Журнал аудита | `<workspace>/.metadata/.config/ai-sql-audit.jsonl` |
| Макросы | `<workspace>/.metadata/.config/ai-macros/` |
| Журнал DBeaver | `<workspace>/.metadata/.log` |

Проверка аудита из терминала:

```bash
./releng/verify-audit.py
# или: ./releng/verify-audit.py "<workspace>/.metadata/.config/ai-sql-audit.jsonl"
```

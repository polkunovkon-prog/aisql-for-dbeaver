# Тестирование AI SQL for DBeaver

## 1. Автоматические тесты (офлайн)

```bash
./releng/test.sh
```

Что происходит: сборка бандлов → компиляция `tests/src/**` → запуск обычной JVM
с jar-ами DBeaver в classpath. Каталог настроек подменяется через
`-Daisql.config.dir=<temp>`, рабочие настройки не затрагиваются.

Покрытие (191 проверка):

| Набор | Что проверяет |
|---|---|
| `GlobsTest` | маски `*`/`?`, регистронезависимость, `matchQualified` |
| `SqlClassifierTest` | read-only/write, `SELECT … INTO`, TCL, UNKNOWN-ключевые слова, EXPLAIN ANALYZE, скрипт из нескольких операторов |
| `MaskingRulesTest` | разбор правил, комментарии, сопоставление по имени/подписи/маске, замена по умолчанию |
| `ConnectionProfilesTest` | default/exact/glob-разрешение профилей, неизвестное значение |
| `QueryPolicyTest` | READ_ONLY-запреты, `policy.forbidden`, FULL игнорирует ограничения |
| `AisqlAuditTest` | цепочка SHA-256, обнаружение подмены, `redactLiterals`, ротация и непрерывность цепочки |
| `PromptBuilderTest` | промпты «выделил → спросил», усечение, заголовки |
| `AiEditLogicTest` | промпты правки выделения, снятие markdown-обёрток и вводных фраз, лимит выделения |
| `AiEditDiffTest` | построчный дифф: замены/вставки/удаления, блоки подряд и далёкие замены, CRLF и хвостовые переводы строк, инвариант «все замены == ответ модели», фолбэк на слишком большом фрагменте |

Добавление проверок — новый класс в `tests/src/com/aisql/dbeaver/tests/`
с методом `run()`, вызов в `AllTests`.

## 2. Ручной чек-лист приёмки (в интерфейсе DBeaver)

Выполняется после `sudo ./releng/install.sh` и запуска DBeaver.
Результат каждого пункта отмечается; при сбое — приложите текст ошибки из чата
и хвост `<workspace>/.metadata/.log`.

### 0. Предварительно

- [ ] DBeaver запущен, есть активное подключение к тестовой БД;
- [ ] Preferences → AI → «Инструменты ИИ»: в списке **11** функций
      (`db_runQuery`, `db_executeSql`, `db_getContext`, `db_listObjects`,
      `db_getObjectDdl`, `db_explain`, `db_help`, `db_listMacros`,
      `db_runMacro`, `db_defineMacro`, `db_deleteMacro`);
- [ ] Preferences → AI → «AI SQL: инструменты SQL» — страница открывается.

### 1. Чтение данных

| # | Действие | Ожидание |
|---|---|---|
| 1.1 | «Сколько строк в таблице `<имя>`?» | `db_runQuery`, число строк |
| 1.2 | «Покажи первые 5 строк `<имя>`» | таблица в ответе |
| 1.3 | «Какие таблицы в базе?» | `db_listObjects` |
| 1.4 | «Какая СУБД, версия, пользователь, схема?» | `db_getContext` |

### 4. Транзакции и автокоммит

- [ ] `write.disableAutocommit=true` (по умолчанию); после `INSERT`/`CREATE`
      Commit (Ctrl+.) фиксирует, Rollback откатывает;
- [ ] `db_getContext` показывает состояние автокоммита.

### 5. Безопасность (профили, запреты, права)

| # | Действие | Ожидание |
|---|---|---|
| 5.1 | В `db_runQuery` (strict) попросить INSERT; если модель откажется сама, сформулировать жёстче: «вызови именно `db_runQuery`» | отклонение с подсказкой про `db_executeSql` (самоотказ модели — тоже корректный исход) |
| 5.2 | Подключение с `policy.profile.<маска>=READ_ONLY`; «вставь строку» | отказ по профилю, запрос не выполнен |
| 5.3 | `policy.forbidden=DROP\s+TABLE`, попросить «удали таблицу» | блокировка с именем правила |
| 5.4 | `mask.rules=*.password=***`; выбрать эту колонку | в ответе `***`, не реальное значение |
| 5.5 | Подключиться ролью «только чтение» и попросить INSERT | ошибка прав СУБД, не «успех» |
| 5.6 | В `db_runQuery` попросить за один вызов два запроса через `;` | отклонение: `runQuery` принимает ровно один оператор |

### 7. Справка

- [ ] «Какими инструментами SQL ты располагаешь?» → `db_help`.

### 8. Журнал аудита

- [ ] Кнопка «Открыть журнал аудита» открывает `ai-sql-audit.jsonl`;
- [ ] каждая строка содержит `function`, `decision`, `sql` (где есть), `outcome`;
- [ ] `./releng/verify-audit.py <файл>` → «цепочка валидна»;
- [ ] правка строки вручную → проверка сообщает о разрыве (можно откатить
      восстановлением файла из копии).

## 3. Что приложить, если что-то не так

1. точный текст из ИИ-чата (и какая функция вызывалась — видно в карточке);
2. `tail -60 <workspace>/.metadata/.log`;
3. `tail -5 <workspace>/.metadata/.config/ai-sql-audit.jsonl`;
4. версию сборки: `cat dist/BUILD-INFO.txt`.

# История версий

## 1.2.1 — 2026-10-17

**Исправлено**

- «Ошибка генерации: OpenAI API token is not set» при первой правке
  в свежей сессии DBeaver: токен профиля хранится в защищённом хранилище
  и подтягивается лениво — до сих пор это делал только штатный ИИ-чат
  перед своим запросом, поэтому правка работала лишь «после чата». Плагин
  теперь сам вызывает `resolveSecrets()` перед созданием движка: Ctrl+Alt+E
  работает сразу после запуска DBeaver (проверка — [TESTING.md](TESTING.md),
  пункт 10.16);
- сообщения об ошибках генерации дополняются понятной причиной:
  «Request failed» → «сервер модели не ответил или оборвал соединение,
  проверьте, что он доступен и не перегружен»; «token is not set» →
  «в настройках ИИ DBeaver не задан API-ключ (Preferences → AI)».
  Таймаут ожидания ответа задаётся в DBeaver (`Preferences → AI`,
  ключ `gpt.timeout`; в нашем окружении 900 секунд).

## 1.2.0 — 2026-10-17

Точечные замены в правке выделения (`Ctrl+Alt+E`, план «Ф2»): вместо ответа
целиком редактор показывает список конкретных замен — «было» подсвечено
красным, «стало» — зелёным; замены можно снимать галочками, просматривать
по одной и применять выборочно.

**Новое**

- дифф на клиенте (`AiEditDiff`, построчный LCS): модель, как и раньше,
  возвращает полный текст фрагмента, а плагин сам строит список замен —
  слабой локальной модели не нужно соблюдать формат правок;
- предпросмотр в редакторе: удаляемый текст — красный фон с зачёркиванием,
  новый — зелёный текст в зарезервированном месте строки
  (`StyledText.setLineVerticalIndent`); документ до применения не меняется,
  нумерация строк не сдвигается;
- карточка: список замен с галочками («Замена N · стр. X–Y» + мера изменения
  «−N +M»), переход `Alt+↓`/`Alt+↑` (в редакторе и в списке), активная
  замена обведена рамкой, снятая — приглушена, кнопки «Применить (N из M)»,
  «Применить все», «Отметить все/Снять все»;
- выборочное применение — по-прежнему одна операция (`IRewriteTarget`,
  compound change): один `Ctrl+Z` отменяет всю правку;
- настройка `edit.previewMode`: `diff` (по умолчанию — точечные замены)
  или `full` (прежний «призрак» с ответом целиком, запасной режим);
- изменение документа после генерации снимает предпросмотр: статус
  «устарело», карточка предлагает запустить правку заново — применение
  заведомо устаревших замен невозможно;
- аудит `ai_edit`: в `detail` добавлены режим диффа (`diff|full`) и число
  замен («применено замен: N из M»).

**Ограничения**

- дифф ограничен размером LCS (~4 млн ячеек): на очень больших фрагментах
  (тысячи строк) предпросмотр вырождается в одну замену «весь фрагмент» —
  применяется всё сразу, как в 1.1.0;
- в режиме `edit.previewMode=full` красно-зелёной подсветки нет (прежнее
  поведение «призрака»).

## 1.1.0 — 2026-10-17

Правка выделения ИИ прямо в SQL-редакторе (по мотивам Zed): выделил фрагмент →
`Ctrl+Alt+E` → инструкция → генерация → предпросмотр замены в редакторе →
«Применить» (или «В чат» / «Отмена»).

**Новое**

- команда `com.pka.dbeaver.aisql.commands.editSelection` (`Ctrl+Alt+E`
  в SQL-редакторе) + пункт контекстного меню «Править выделенное ИИ»;
- карточка правки: поле инструкции (Enter — сгенерировать, Esc — отмена),
  кнопки «Сгенерировать», «Применить», «В чат», «Отмена»;
- потоковый «призрачный» предпросмотр замены прямо в редакторе (штатный
  `SQLSuggestionTextPainter`, собственная копия; зелёный текст на светлом
  фоне). Текст печатается по мере генерации;
- применение — одной операцией (`IRewriteTarget`, compound change): один
  `Ctrl+Z` отменяет всю правку; перед применением проверяется, что текст
  редактора не изменился, иначе правка отклоняется с предупреждением;
- режимы `edit.applyMode`: `preview` (по умолчанию — применение по кнопке)
  и `direct` (применять сразу после генерации);
- настройки: `edit.enabled`, `edit.applyMode`, `edit.maxSelectionChars`
  (4000), `edit.audit`; секция «Правка выделения с ИИ» на странице настроек;
- генерация — штатным профилем ИИ DBeaver (тем же, что у чата): повторно
  настраивать модель/URL/ключ не нужно; при недоступности потокового режима
  используется обычный запрос целиком;
- события аудита `ai_edit` (applied / canceled / chat / error): режим, размеры
  фрагмента и результата, инструкция (одной строкой, до 160 символов).
  Текст фрагмента и ответ модели в журнал не пишутся;
- «В чат» — страховочный путь: тот же запрос уходит в ИИ-чат без применения.

**Инфраструктура**

- `install.sh` при смене версии корректно обновляет установку: прежние jar-ы
  плагина удаляются из `dropins/plugins`, а записи плагина в `bundles.info`
  перезаписываются на новые (с сохранением копии файла). Без этого Equinox
  продолжал бы загружать бандл прежней версии по старой записи; повторный
  запуск без изменений `bundles.info` не трогает.

**Ограничения**

- предпросмотр — вставка «призрака», без красно-зелёного сравнения
  (план Ф2, см. `docs/ROADMAP.md`).

## 1.0.0 — 2026-10-16

Первая версия «ИИ-исполнитель SQL» для DBeaver CE 26.2.2. Полная переработка
пилотного (патченного) плагина в самостоятельные OSGi-бандлы.

**Состав**

- два бандла: `com.pka.dbeaver.aisql.core` (логика, функции) и
  `com.pka.dbeaver.aisql.ui` (команды, страница настроек, промпты);
- 11 функций тулбокса `db` в штатной точке расширения `com.dbeaver.ai.function`
  (`runQuery`, `executeSql`, `getContext`, `listObjects`, `getObjectDdl`,
  `explain`, `help`, `listMacros`, `runMacro`, `defineMacro`, `deleteMacro`);
- команды «выделил → спросил»: `Ctrl+Alt+A` (SQL-редактор),
  `Ctrl+Alt+I` (таблица результатов); вставка промпта в ИИ-чат без автоотправки;
- страница настроек `AI → «AI SQL: инструменты SQL»` (+ кнопка в панели
  ИИ-чата); id страницы — `com.dbeaver.preferences.ai.tools` (именно его
  открывает пункт «Configure AI Tools…» в карточках ИИ).

**Исправлено по итогам приёмочного теста (16.10.2026)**

- ядро помечено `singleton:=true` — без этого Equinox игнорировал все его
  расширения, и 11 функций `db_*` не попадали в ИИ-чат («нет инструментов
  для выполнения запросов»);
- страница настроек регистрируется статически (динамический alias-регистратор
  удалён) — пункт «Configure AI Tools…» в карточках подтверждения теперь
  открывает настройки плагина;
- восстановлен стартовый маркер в журнале: лёгкий хук `org.eclipse.ui.startup`
  активирует UI-бандл при старте рабочей среды (строки «AI SQL UI/core plugin
  started» в `dbeaver-debug.log` появляются сразу, а не при первом обращении
  к чату). Это нужно контрольному запуску `install.sh` и диагностике;
  сломанный динамический alias-регистратор при этом не возвращался;
- `install.sh`/`uninstall.sh` принудительно сбрасывают служебные кэши Equinox
  во всех известных областях конфигурации: системной
  (`/usr/share/dbeaver-ce/configuration`, её используют запуски от root),
  персональной install-data
  (`~/.local/share/DBeaverData/install-data/<product>/<version>/` — рабочий
  случай пользователя: DBeaver уводит туда configuration, когда системная
  недоступна на запись) и следах старых Eclipse в домашнем каталоге
  (`~/eclipse/configuration`, `~/.eclipse/*/configuration`). Фреймворк
  кэширует там манифесты бандлов (`org.eclipse.osgi`) и модель реестра
  расширений (`org.eclipse.core.runtime`) и при совпадении пути и версии
  переиспользует старые данные: без сброса расширения игнорировались, а
  ранний старт пытался загрузить удалённый класс старой сборки
  (`PreferenceAliasRegistrar`). При неудачной контрольной проверке `install.sh`
  печатает диагноз из журнала; если DBeaver пользователя запущен, установка
  предупреждает, что его нужно закрыть (иначе кэш восстановится при выходе).

**Безопасность**

- классификация SQL на основе парсера DBeaver (SQLScriptParser/SQLQuery) —
  без токенных эвристик; `SELECT … INTO` трактуется как запись;
- профили подключений `READ_ONLY` / `STANDARD` (по умолчанию) / `FULL`
  с масками имён (`policy.profile.<маска>`); `EXPLAIN ANALYZE` в READ_ONLY
  запрещён;
- `runQuery.strictReadOnly` (по умолчанию включён);
- `policy.forbidden` — regex-запреты (DROP, TRUNCATE и т.п.) во всех профилях,
  кроме FULL;
- отключение автокоммита перед изменяющими операторами с возможностью отката;
- маскирование значений секретных колонок до отправки в модель
  (`mask.enabled`, `mask.rules`);
- лимиты: строк (200, потолок 5000), таймаут (60 с), размер вывода для модели
  (40 000 символов), размер макроса (64 КиБ).

**Аудит v2**

- журнал `ai-sql-audit.jsonl` с цепочкой SHA-256 (`prev`/`hash`), ротацией
  (`audit.maxBytes`, `audit.maxFiles`) и опциональным редактированием
  строковых литералов (`audit.redactLiterals`);
- утилита проверки `releng/verify-audit.py`; старый `ai-sql-audit.log`
  не используется и не удаляется.

**Инфраструктура**

- сборка без Maven/Tycho: `releng/build.sh` (javac против установленного
  DBeaver; `dist/`, `SHA256SUMS`, `BUILD-INFO.txt`);
- офлайн-тесты `releng/test.sh` (105 проверок, plain Java);
- установка/удаление `releng/install.sh` / `releng/uninstall.sh`
  (dropins + идемпотентная запись в `bundles.info` с резервной копией;
  контрольный headless-запуск от имени рабочего пользователя; миграция
  со старого патченного плагина);
- документация `docs/` (INSTALL, USAGE, SECURITY, TESTING, ADR).

**Известные ограничения**

- совместимость с другими версиями DBeaver не заявляется (целевая — 26.2.2);
- `Ctrl+Alt+A`/`Ctrl+Alt+I` могут конфликтовать с локальными раскладками
  клавиатуры — переназначаются штатными средствами (`Preferences → Keys`).
